## 7. VISA SPONSORSHIP INTELLIGENCE ENGINE

This is one of the most important features.

For every job, extract sponsorship and relocation information from the original employer job description and available employer documentation.

Classify each job into:

1. CONFIRMED
   - Job explicitly states visa sponsorship is available.
   - Employer confirms work permit sponsorship.
   - Employer explicitly supports international relocation and required work authorization.

2. LIKELY
   - Employer has relevant sponsorship history or verified sponsor status.
   - The specific vacancy does not explicitly confirm sponsorship.

3. UNVERIFIED
   - Sponsorship information is unavailable or unclear.

4. UNAVAILABLE
   - Job explicitly states no sponsorship.
   - Vacancy requires existing work authorization that the candidate does not have.

Extract evidence, not just labels.

Required fields:
- sponsorship_status
- sponsorship_evidence
- sponsorship_source_url
- employer_sponsor_verified
- relocation_support
- relocation_evidence
- work_authorization_requirement
- candidate_eligibility
- verification_timestamp

Never claim that sponsorship is confirmed without vacancy-specific evidence.

Display the original supporting sentence or a short factual excerpt.

Distinguish:
- Visa sponsorship
- Work permit support
- Relocation package
- Existing work authorization required
- Remote international employment
- Contractor-only arrangements

A company sponsor register is supporting evidence, not proof of sponsorship for the individual job.

## 12. AUTOMATED DAILY EXECUTION — FREE INFRASTRUCTURE

Use GitHub Actions scheduled workflows.

The system should run daily at approximately 03:00 UTC, with manual execution also supported.

Example workflow:

name: Global AI JobPilot Daily Search

on:
  schedule:
    - cron: "0 3 * * *"
  workflow_dispatch:

jobs:
  collect-jobs:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install dependencies
        run: pip install -r backend/requirements.txt

      - name: Run daily collection
        env:
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_SERVICE_ROLE_KEY: ${{ secrets.SUPABASE_SERVICE_ROLE_KEY }}
          DISCORD_WEBHOOK_URL: ${{ secrets.DISCORD_WEBHOOK_URL }}
          SMTP_EMAIL: ${{ secrets.SMTP_EMAIL }}
          SMTP_PASSWORD: ${{ secrets.SMTP_PASSWORD }}
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        run: python -m app.main --mode daily

Ensure the working directory and Python import paths are correct.

Important:
- Use GitHub Actions free usage allowances.
- Do not run an unnecessary always-on backend.
- Avoid excessive workflow executions.
- Implement a manual run command.
- Add execution logs and failure notifications where practical.
- Do not rely on GitHub Actions as a guaranteed real-time scheduler.

Use only trusted, pinned GitHub Actions versions and review permissions.
